🗂️ About the Server Registry

The Server Registry lets you save servers and monitor them continuously in the background, instead of running a one-off lookup each time. Register a server once, then start monitoring to get automatic status checks on a schedule.

Buttons

  • Add Server — registers a new server by name and IP, and runs an initial intelligence lookup on it.
  • Start Monitoring — begins automatic background checks at a chosen interval (e.g. every 60 seconds).
  • Stop Monitoring — pauses the background checks for that server.
  • Check Now — runs a single check immediately, without waiting for the next scheduled interval.
  • Discover Domains — searches certificate transparency logs, DNS, and reverse-IP lookups for domains/websites hosted on this server's IP.
  • View — opens full detail, live status, and check history for a registered server.
  • Remove — deletes a server from the registry (also stops its monitoring).

Terms

  • Interval — how often the background monitor re-checks the server (e.g. every 30s, 60s, 5 min).
  • Consecutive failures — how many checks in a row have failed; a server is marked DOWN after a couple of failures in a row, to avoid false alarms from one dropped packet.
  • Latency — how long the server took to respond to the last check, in milliseconds.
  • History — the rolling log of past check results for a server (status + latency over time).

Domains & Websites

Candidates come from four sources: the server's TLS certificate (SNI-aware), reverse DNS, a reverse-IP lookup, and Certificate Transparency logs. Free public sources are result-capped by their provider, so on a server with many domains this may not be exhaustive on its own — paste any domains you already know about below and they'll be verified alongside whatever auto-discovery finds. Each domain is classified by how much has been confirmed: Candidate (found, not yet checked) → DNS-Associated (resolves elsewhere) / DNS-Verified (resolves here) → Verified Website (resolves here and responded over HTTP/S).
